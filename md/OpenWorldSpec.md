# 오픈월드 설계 스펙 (ARCHÉ / G.S.I)

본 문서는 대규모 오픈월드 개발을 위한 **고정 기준**과 **권장 초기 수치**를 정리한다. 수치는 프로토타입 후 플레이 테스트로 조정한다.

---

## 1. 목표·톤

| 항목 | 내용 |
|------|------|
| 월드 스케일 | 매우 큼. 전 구역을 균일한 고디테일로 만들지 않음. |
| 근거리 | 디테일 (소품, 잔디, 작은 오브젝트 등). |
| 원거리 | 큰 실루엣 (큰 나무, 산맥, 지형 윤곽), 저폴리. |
| 그래픽 | 실사 지양. **동화·스토리북** 느낌, 저폴리, **저사양** 목표. |
| 카메라 | 본편 **1인칭**. 개발·디버그용 **3인칭** 병행 (동일 스트리밍 규칙). |
| 팀 | 1인 개발, AI 도구 적극 활용. |

---

## 2. 이동 속도 (m/s)

플레이어 기준 **월드 단위는 미터(m)** 로 통일한다.

### 2.1 확정값 (기획 입력)

| 상태 | 속도 (m/s) |
|------|------------|
| 도보 (걷기) | **1.4** |
| 도보 (달리기) | **6.5** |
| 말 탑승 · 걷기 | **1.8** |
| 말 탑승 · 달리기 | **10.0** |

### 2.2 권장값 (스트리밍·LOD를 한 세트로 유지하기 위한 보조 결정)

비행이 말 전력 직선보다 지나치게 빠르면 **로드 반경을 이동 수단마다 두 벌**로 나눠야 하므로, **최고 속도 대비 최저 도보** 비율을 과도하게 벌리지 않는다.

| 상태 | 속도 (m/s) | 비고 |
|------|------------|------|
| 비행 · 순항 (수평) | **12.0** | 말 전력(10.0) 대비 약 1.2배. 탐험용. |
| 비행 · 부스트 (짧은 구간) | **15.0** | 스트리밍·LOD **최악 시나리오** 설계에 사용. 상시 유지는 피하는 것을 권장. |
| 비행 · 상승/하강 | **6.0** | 수직만 과도하게 빠르지 않게. |

**참고:** 스트리밍 반경·타일 갱신 주기를 잡을 때 **최고 속도 ≈ 15 m/s** 를 상한으로 두면, 도보 1.4 m/s 대비 약 **10.7배** 이내로 동작 범위가 묶인다.

## 3. 월드 분할·스트리밍 (권장 초기값)

| 항목 | 값 | 비고 |
|------|-----|------|
| 섹터(타일) 한 변 | **512 m** | Unity Terrain 1개/섹터 등 작업 단위로 쓰기 쉬운 크기. |
| 동시 로드 섹터 | **5 × 5** | 플레이어 격자 기준 주변 로드. |
| 물리·상호작용 밀도 | **3 × 3** (가운데) | 콜라이더·스폰·중요 연출 우선. |
| 언로드 | 중심에서 **맨해튼 거리 2 초과** 격자는 언로드 후보 | 구현 시 여유 버퍼(예: +1 격자) 권장. |
| 세로 한계 (월드) | 지형 **Y −200 ~ +400 m** (초안) | 비행·낙하·터널 여유. 실제 맵에 맞게 수정. |

**구현 방향:** Unity **URP** 유지, 콘텐츠는 **Addressables** 로 섹터(또는 구역) 단위 로드. (프로젝트에 패키지 존재.)

**Addressables 그룹 네이밍 예:** `World_Sector_{x}_{z}` (격자 인덱스 정수).

## 4. 렌더링·원거리 (권장 초기값)

| 항목 | 값 | 비고 |
|------|-----|------|
| 안개 (시작 거리) | **180 ~ 250 m** | 동화 톤이면 강한 포그도 자연스러움. |
| 안개 (완전 머지) | **600 ~ 900 m** | 저폴리·실루엣 위주 구간과 맞춤. |
| 오브젝트 LOD | **3단** (근·중·원) | LOD Group 기준 거리는 프로토타입 씬에서 수치 확정. |
| 지형 | Terrain 내장 거리·픽셀 오차 조절 + 필요 시 원거리 단순 메시 레이어는 추후. |
| 나무·식생 (원거리) | **빌보드 또는 큰 저폴리 실루엣** | 가까운 곳만 개별 메시 밀도 높게. |

## 5. 내비게이션·이동 (권장)

| 항목 | 내용 |
|------|------|
| 도보·말 (지상) | **NavMesh** 또는 동등한 지상 이동 검증. |
| 비행 | 전역 NavMesh 의존 최소화. **비행 허용 볼륨** 또는 고도만 제한하는 방식 검토. |
| 말 | 지형 경사·낭떠러지는 **말 탑승 시** 추가 규칙으로 처리. |

---

## 6. 성능·저장소 (권장)

| 항목 | 내용 |
|------|------|
| 목표 | **저사양 PC** 가 가동 가능한 선에서 우선 (구체 FPS는 하드웨어 목표 정한 뒤 표에 추가). |
| Git 대용량 | TerrainData·대형 텍스처는 **Git LFS** 사용 권장. |

---

## 7. 월드 제작 파이프라인 (순서)

1. 대략 지도 (바다·산·길·바이옴 구역만).  
2. 블록아웃 (이동·시야 검증).  
3. 섹터 단위 지형·레이어.  
4. 오브젝트 배치 규칙 (인스턴싱·프리팹).  
5. 플레이어브 영역 위주 내비·콜라이더.  
6. 스트리밍·LOD·포그·품질 패스.
